① 为什么需要固定工作流

一句话

固定工作流不是束缚你——它是在帮你避免"AI写了什么我没看就提交了"这种灾难。

数据说话：用固定工作流的开发者，人均 Bug 率降低 ~60%，代码审查通过率提高 ~40%。不是因为 AI 变聪明了，而是因为人类的审查环节没有被跳过去。

四条铁律

🔍 必审查

✅ 必测试

build + test 通过才提交，不侥幸

📝 细提交

commit message 写清楚做了什么、为什么

③ 每个环节具体做什么

① /plan — 先想清楚

只在复杂任务时用（多文件、新功能、重构）。简单任务跳过，别过度使用。

② 写代码 — AI 实现

确认计划后让 Claude 写。过程中如果跑偏，直接纠正——"不对，我要的是XX"。发现方向完全错了就 /clear 重来。

③ /code-review — 必做！

这是最重要的环节。AI 写的代码会犯低级错误：引用不存在的变量、忘记处理边界情况、写了 hardcode 的测试值……必须审查。

审查后 AI 给的修改建议，也要检查——不要盲信审查结果。

④ 跑测试 — 机械验证

npm run build + npm test。别跳过——很多问题代码审查看不出来，但编译器/测试跑不过。这个环节是纯机械的，不应该有任何侥幸。

⑤ git diff — 肉眼确认

提交前最后看一眼改了哪些文件。有时候 AI 会意外修改你不想动的文件——git diff 能抓到。

⑥ commit — 写好信息

用约定式提交格式（feat:/fix:/refactor:），写清楚做了什么。可以让 Claude 帮你写 commit message：

帮我写一个 commit message，描述这次的改动

④ 好习惯 vs 烂习惯

环节❌ 烂习惯✅ 好习惯
规划 改了5个文件才想起来该用 /plan 动手前问自己：超过2个文件？先 /plan
编码 AI 写了 300 行才去看 每完成一个独立功能就看一次
审查 太信任，直接跳过 每次必做，AI 的审查建议也要验证
测试 "看起来没问题，不用跑了吧" build + test 不通过不提交
提交 commit message 写 "update" "feat: 添加导出CSV功能，支持时间范围筛选"
最危险的错觉："这次改动很小，不用审查了。"——绝大多数 Bug 就出在"这次改动很小"的时候。小改动也可能引入大问题。

⑤ 常用命令串联速查

场景命令序列
新功能 /plan → OK → 实现 → /code-review → 修复 → 测试 → commit
修 Bug 描述Bug → 实现修复 → /code-review → 测试 → commit
重构 /plan → OK → 逐步实现 → 每步审查 → 全量测试 → commit
审查+安全 /code-review → 修复HIGH → /security-review → 修复CRITICAL → commit
写测试 写测试 → 验证通过 → /code-review（测试代码也要审）→ commit
效率提示：Claude Code 可以并行启动多个子代理。如果改动涉及安全和性能两个方面，可以同时启动 security-reviewer 和 performance-optimizer 审查。

⑥ 用工作流完成一个小任务

练习：在任意项目里，完整走一遍这个流程：

  1. /plan — 做一个简单功能（比如"加一个回到顶部按钮"）
  2. 确认计划 → 让 Claude 实现
  3. /code-review — 审查产出
  4. 如果有问题 → 修复 → 再审查
  5. npm run build（或项目对应命令）— 验证构建
  6. git diff — 看改动文件
  7. git commit — 写清楚提交信息

走完一遍大概 10 分钟。关键不是快，是每个环节都做到——形成肌肉记忆。

⑦ 快速掌握清单

  1. 记住六步闭环：plan → 编码 → review → 测试 → diff → commit
  2. 每次写完代码立即 review，不等积压
  3. build + test 不通过绝不提交
  4. commit message 写清楚做了什么
  5. 别跳过 git diff——AI 可能改了你不打算改的文件
  6. 小改动也要走流程，别侥幸

⑨ 总结：最常用 & 最易错

🎯 每天必做的 6 步

  • /plan — 新功能/重构前做计划（2分钟）
  • 编码 — AI 实现，你边看边纠正
  • /code-review — 审查每个改动（3分钟，值！）
  • build + test — 不通过不提交（2分钟）
  • git diff — 扫一眼所有改动的文件（30秒）
  • git commit — 写清楚信息，让 Claude 帮你写（1分钟）

⚠️ 最常跳过的环节（也是出事最多的）

  • 跳过 code review — "AI 写的肯定没问题" → 最多 Bug
  • 跳过测试验证 — "就改了两行不用跑" → 构建失败才发现
  • 跳过 git diff — "就改了一个文件" → AI 改了三个你不知道
  • 提交信息敷衍 — "update" → 两周后你完全不知道这次改了什么
  • 小改动不走流程 — "就改一行" → 改错了一行，炸了整个页面
