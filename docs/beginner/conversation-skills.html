① Claude Code 怎么"听"你的话

一句话

Claude 不是读心术——你给的上下文越具体，它产出的代码越准确。模糊的输入 = 模糊的输出。

关键认知：Claude Code 在对话开始时会读取项目结构（CLAUDE.md、文件树等），但它不会自动理解你"脑子里想的是什么"。你需要用清晰的语言描述你的意图，就像跟一个新加入团队的同事讲话一样。

对话质量的三个决定因素

📋 上下文

你有没有让它先读相关文件？有没有说清楚背景？

🎯 目标清晰度

"加个功能" vs "在用户设置页加一个导出 CSV 的按钮"

🔄 迭代方式

跑偏了是纠正还是重开？上下文乱了知不知道清空？

② 万能提问公式：背景 + 目标 + 约束

公式

[背景] 我在做XX项目，用的是YY技术栈，相关文件在ZZ [目标] 我想实现AA功能 / 修复BB问题 / 理解CC逻辑 [约束] 要求：XXX，不要：YYY，注意：ZZZ

拆解示例

❌ 模糊版

"帮我优化一下性能"

Claude 不知道哪个文件、哪种性能、什么指标，只能瞎猜。

✅ 公式版

"pages/dashboard.tsx 首页加载要 5 秒。帮我把 useEffect 里的数据请求改成并行加载，首屏渲染控制在 1 秒内。不要改 UI 结构，只改数据层。"

❌ 模糊版

"帮我加个登录功能"

✅ 公式版

"在 app/ 下新建 auth/ 目录，用 JWT + httpOnly cookie 做登录。后端用 FastAPI，前端 React。只做邮箱+密码一种方式，先别做 OAuth。"

③ 不同场景的提问策略

场景策略示例开头
理解代码 指定文件 + 具体问题 "src/utils/auth.ts 里这个函数是干什么的"
写新功能 背景 + 目标 + 约束（用 /plan） "/plan 在 settings 页加导出 CSV 按钮"
改已有代码 先让 Claude 读文件，再提修改 "先读 components/Nav.tsx，然后把 logo 改成可点击的"
修 Bug 贴报错 + 相关文件 "npm run build 报这个错 [贴错误]，相关文件在 src/build/"
技术选型 给选项 + 让 AI 对比 "这个项目该用 Zustand 还是 Redux？帮我列利弊"

④ 好习惯 vs 烂习惯

❌ 烂习惯✅ 好习惯
开篇 "帮我看看" 先说 /plan 或说清楚要做什么
上下文 不提文件，让 AI 自己找 "先读 XX 文件"，再提需求
迭代 跑偏了还在追着问 发现偏了立刻 /clear 重来
信任 全部接受，不审查 每轮用 /code-review 检查
任务拆分 一个大任务聊到底 拆成小任务，每次独立会话
纠错 "你又错了"（没有帮助） "不对，我要的是XX，不是YY。重来"
最坑的习惯：在一个会话里堆 10 个任务。上下文越长 Claude 越笨——它会把前面的对话当参考，产生混乱。一个新任务 = 一个新会话。

⑤ 高效迭代：错了怎么纠正

提出需求
背景+目标+约束
→
看产出
读代码+测试
→
纠正/确认
不对就具体说哪里不对

纠正的三种方式

小偏差：直接说"不对，XXX 应该是 YYY，改一下"

方向错了："停。我重新描述需求：[重新描述]"

上下文乱了：/clear 然后重新开始，把关键上下文再给一次

什么时候果断 /clear：连续纠正 3 次还不对、Claude 开始重复之前的代码、输出越来越长但不解决问题——说明上下文已经脏了，清空比重写更快。

⑥ 改造练习：把模糊需求变清晰

练习 1：把下面这句话改写成"背景+目标+约束"格式：

"帮我改一下登录页面"

点击看参考改写

"改 pages/login.tsx。把背景色换成品牌色 #1a1a2e，登录按钮改成圆角 8px，hover 时颜色加深。不要动布局和表单逻辑。"

练习 2：把下面这句话改写成"背景+目标+约束"格式：

"帮我优化一下数据库查询"

点击看参考改写

"services/user.ts 的 getUserList 现在一次查 5000 条，页面慢。帮我加分页（每页 20 条），用 Prisma 的 skip+take。不要改返回的数据结构，前端还在用。"

练习 3：你最近一次跟 Claude Code 对话，能不能用公式重写一遍？试试看。

⑦ 快速掌握清单

  1. 记牢公式：背景 + 目标 + 约束
  2. 大任务先用 /plan 拆解，小任务直接说
  3. 提问前先说文件名，让 Claude 先读
  4. 纠错时具体说"哪里不对"，不要只说"错了"
  5. 连续 3 次纠正无效 → /clear，重开
  6. 每次产出用 /code-review 检查

⑨ 总结：最常用 & 最易错

🎯 最常用提问模板

  • 读文件 — "先读 XX 文件，告诉我这段逻辑是干什么的"
  • 写功能 — "/plan 在 XX 文件做 YY 功能，要求 ZZ"
  • 修 Bug — "YY 文件第 N 行这里报错 [贴错误]，帮我修"
  • 重构 — "把这个文件里重复的 XX 逻辑提取成独立函数"
  • 审查 — "/code-review 刚才的改动"

⚠️ 最常犯错误

  • 一句话抛给 AI — "帮我看看这个" = AI 不知道看哪个
  • 不提文件路径 — 不给文件 = AI 只能凭项目结构瞎猜
  • 会话堆满任务 — 上下文污染，越聊越偏
  • 连续纠正不停手 — 3次还不对就该 /clear，不是追问第4次
  • 纠错不说原因 — "错了"没用，"我要XX不要YY"才有用
