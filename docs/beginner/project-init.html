① Claude Code 怎么帮你初始化项目

一句话

Claude Code 可以帮你一次生成完整的项目结构——不仅仅是文件，还包括配置文件、依赖、README、测试框架。

关键认知：手工搭项目要 1-2 小时：创建目录、写 package.json、配 ESLint、装依赖、建文件夹结构……Claude Code 一句命令全搞定。但它生成的配置你需要检查——不是因为它会出错，而是有些选择要你自己确认。

② 启动新项目的三种方式

方式一：从零生成（最灵活）

帮我创建一个 React + TypeScript + Vite 项目。 要求：ESLint用airbnb风格，测试用Vitest， 目录结构：src/components/ src/hooks/ src/lib/ tests/

Claude 会逐文件创建：package.json、vite.config.ts、tsconfig.json、src/ 目录树、一个示例组件 + 测试。

方式二：克隆模板后定制（最快）

# 先用 create-vite 生成骨架 npm create vite@latest my-app -- --template react-ts # 再让 Claude 按你的需求定制 claude > 我刚用 create-vite 建了项目，帮我加 Tailwind、Vitest 和 CLAUDE.md

方式三：从已有项目复制结构（最省心）

> 参考 everything-claude-code 的项目结构，帮我创建一个新项目。 技术栈换成 FastAPI + SQLAlchemy，目录结构类似。

给一个参考项目路径，Claude 会学习它的结构并适配到新技术栈。

③ 初始化项目时别漏了 CLAUDE.md

CLAUDE.md 是 Claude Code 的"项目说明书"

放在项目根目录，Claude 每次启动会自动读取。它告诉 Claude：

  • 项目的技术栈和框架版本
  • 目录结构说明（哪个目录放什么）
  • 编码规范（命名、格式化、测试要求）
  • 常用命令（build、test、lint）
# CLAUDE.md 示例片段 ## Tech Stack - Next.js 14 (App Router) + TypeScript - Prisma ORM + PostgreSQL - Tailwind CSS + shadcn/ui ## Commands - Build: `pnpm build` - Test: `pnpm test -- --coverage` - Lint: `pnpm lint` ## Conventions - 组件用 PascalCase，文件同名 - 每个组件要有 loading/error 状态 - API 返回统一用 { success, data, error } 格式
创建 CLAUDE.md 最简单的方法：项目搭好后说 "帮我写一份 CLAUDE.md"，Claude 会扫描项目结构自动生成。

④ 好 vs 烂：初始化项目的常见坑

❌ 烂✅ 好
需求描述 "帮我搭个项目" "React+TS+Vite，ESLint airbnb，Vitest"
配置文件 全部接受默认值 逐一检查 tsconfig、ESLint 规则是否符合团队规范
CLAUDE.md 跳过不写 搭完就让 Claude 生成，是第一优先级
目录结构 让 Claude 自由发挥 先说你想要的目录结构，参考已有项目
验证 创建完就不管了 立刻 npm install + npm run build 验证能跑
最常见的翻车：Claude 创建了一堆文件，你没立刻验证，过了两天才发现项目跑不起来——那时候上下文早丢了，排查成本翻倍。创建完第一件事：跑一遍 build 和 test。

⑦ 快速掌握清单

  1. 描述项目时至少说：框架 + 语言 + 构建工具 + 测试框架
  2. 创建完立刻 npm install + build，验证能跑
  3. 第一时间生成 CLAUDE.md
  4. 检查生成的配置文件是否符合你的习惯
  5. git init + 首次提交，别等写了功能代码再提交

⑨ 总结：最常用 & 最易错

🎯 最常用命令

  • 从零创建 — "帮我创建一个 [框架]+[语言] 项目，用 [规范]"
  • 加配置文件 — "帮我加 ESLint、Prettier 和 tsconfig"
  • 生成 CLAUDE.md — "帮我写一份 CLAUDE.md"
  • 参考已有项目 — "参考 XX 项目的结构，创建新技术栈的新项目"
  • 补全缺失 — "帮我检查项目还缺什么配置文件"

⚠️ 最常犯错误

  • 描述太模糊 — "搭个项目" → Claude 不知道你要什么框架
  • 建完不验证 — 没跑 build，过两天发现项目根本跑不起来
  • 不写 CLAUDE.md — 浪费了 Claude Code 最核心的上下文能力
  • 不检查生成配置 — ESLint 规则可能跟你团队规范有冲突
  • 不初始化 git — 写了半天功能代码才发现还没 init
