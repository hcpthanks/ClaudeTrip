那就是：Agent 产品一般是由 Agent 框架（我称之为"壳"）+ 大模型组成的。在 Claude Code 里，Claude 是大模型，而 Claude Code 是"壳"，Claude 的原生模型在国内确实会被封，很无奈，所以这期视频主要讲如何用 Claude Code 接入 DeepSeek。

虽然 Claude 会被封，但是 Claude Code 就是个"壳"，可以随意使用，搭配任何模型都可以。

今天的办法不用担心封号，也不用魔法，尽可能让所有的朋友都用上，一期 Claude Code 从 0 开始入门的新手教程，它来了。（这里碍于只有 Windows 的环境，所以本期主要是没有魔法的 Windows 环境如何使用 Claude Code 的教程。）

下面有几步准备工作要做：
1. Node.js 安装

直接在对话框输入： 帮我安装 Node.js ，然后耐心等待~

由于 Claude Code 本身就是一个 Node.js 应用，它的源码是用 TypeScript 写的，编译之后跑在 Node.js 运行时上。没有 Node.js，你执行 claude 命令时系统根本不认识它——就跟没有 Python 跑不了 .py 文件一个道理。

具体来说 Node.js 在 Claude Code 里干了三件事：

    运行环境 — Claude Code 的 Agent 循环（理解输入、规划步骤、调工具、读文件、写文件）全部是 Node.js 进程在执行。

    包管理（npm） — 装 Claude Code 本身就是 npm install -g，没有 Node.js 就没有 npm，装都没法装。

    文件系统操作 — Claude Code 读写你的代码文件、执行 shell 命令，底层全靠 Node.js 的 API。

简单来说：Node.js 是 Claude Code 的"地基"，它本身是 Node.js 写出来的，离了 Node.js 跑不起来。

这里我们让 Workbuddy 来帮我们安装 Node.js，Node.js 装完会自带 npm——待会儿 Workbuddy 帮你下 Claude Code，底层调的就是 npm，所以这步不能省。
2. Git 安装

这一步同上，对话框输入： 帮我下载 Git

Git 在 Claude Code 里的作用有两层：

    看 diff 确认修改 — Claude Code 每次改代码前让你确认改了什么，这个功能依赖 Git 的变更追踪。项目没初始化 git，它就不会给你看 diff，直接改。

    管理项目 — Claude 在一个项目里启动时，它能看到 git 状态（哪些文件改了、当前分支是什么），很多 Agent 操作基于这个信息。

所以一句话概括： Node.js 让 Claude Code 能跑，Git 让 Claude Code 能安全地改代码。

这里我再啰嗦一句，Git 和 GitHub 的区别：

    Git — 版本控制工具。跑在你本机上的命令行程序，记录文件变更历史、创建分支、合并代码。离线可用，不依赖任何网络服务。

    GitHub — 托管 Git 仓库的网站。把你的 Git 仓库传到云端，方便多人协作、备份代码。需要联网。

这一步之后，前期的准备工作可以说已经做完了，接下来我们在对话框输入： 帮我下载 Claude Code

二、验证安装

下载完成以后，如果你想确认三样东西是不是都装好了，打开终端，右键"开始菜单"，打开 Windows Powershell (I)，分别敲三个命令：

node --version # 检查 Node.js

git --version # 检查 Git

claude --version # 检查 Claude Code

每个命令都会返回一个版本号。有版本号就说明装好了，没报错就没问题。

这里我们再聊一下为什么要用 Claude Code 接入 DeepSeek。有以下几方面原因，一是部分朋友的确受制于魔法的原因，没办法使用到 Claude Code + Claude Opus/Sonnet/Haiku 的原生模型；二是出于高昂的订阅费用。

有一个比喻我很喜欢：把 Agent 的框架（壳）比作一台车，把大模型比作油。Claude Code 是好车，但是原生的油（即原生的大模型）太贵，我们退而求其次选择稍微便宜但是好用的油，这不失为一种不错的办法。

回归主题，到这里我们的 Claude Code 已经可以正常使用，但是终端页面终究是受到功能的局限，仅仅只有一行命令行，且不能复制输出的内容，不太适合大家使用，于是此时另一个工具登场： Visual Studio Code，即 VS Code 。
