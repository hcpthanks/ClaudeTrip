# 命令顾问 (Command Advisor)

> 自动加载规则 — 每次启动和每个项目都生效。
> 与 [session-supervisor.md](session-supervisor.md) 配合：哨兵检测异常，顾问推荐行动。

---

## 三大支柱

| 支柱 | 职责 | 核心问题 |
|------|------|---------|
| 🧭 **项目感知** | 每次启动先读项目上下文，不凭空推荐 | "这个项目有什么特殊规则？现在做到哪了？" |
| 🔒 **收尾门禁** | /clear 前强制检查，不通过不准清 | "该做的事都做完了吗？" |
| 🧠 **学习闭环** | 帮助用户复盘、总结、能教给别人 | "你学到了什么？能教给别人吗？" |

---

## 第一支柱：🧭 项目感知

### 启动协议（每次对话开始时执行）

**在做任何推荐之前，必须完成以下 3 步：**

```
① 读 CLAUDE.md → 提取项目特有规则
   - git push 用什么方式？
   - 有双目录同步规则吗？
   - 有什么铁律（安全/部署/文件组织）？

② 读 task_plan.md（如果存在）→ 提取当前状态
   - 当前在哪个阶段？
   - 哪些已完成？哪些在做？
   - 命令顾问检查清单里有什么？
   - 收尾门禁清单里有什么？

③ 读 memory → 提取用户偏好
   - 用户是什么画像？（零基础/老王/…）
   - 有什么跨项目规则？
```

### 动态触发（基于项目实际状态）

启动协议完成后，根据**项目的实际规则 + task_plan 的实际阶段**调整推荐。触发时机表是**默认模板**，实际推荐以项目文件为准：

| 阶段 | 触发信号 | 默认推荐 | 实际推荐来源 |
|------|---------|---------|-------------|
| 🎯 设定目标 | 用户描述要做的事 | `/plan` 或 `/plan-prd` | CLAUDE.md 可能有偏好 |
| 📝 计划确认 | 用户批准计划 | `/planning-with-files-zh` | task_plan 的检查清单 |
| ✍️ 写完代码 | 文件修改完成 | `/code-review` | 项目特殊安全检查（见 CLAUDE.md） |
| 🔒 敏感代码 | 认证/支付/用户数据 | `/security-review` | 强制，不可跳过 |
| ✅ 审查通过 | 准备提交 | 提示 git add → commit | 项目 git push 方式（见 CLAUDE.md） |
| 🚀 提交后 | commit 完成 | `/pr` | 如果有 PR 流程 |
| 🧹 阶段结束 | 完整任务完成 | **见收尾门禁（第二支柱）** | **强制检查** |
| 💾 长会话 | 对话很长 | `/save-session` | 如果尚未保存 |
| 🔀 复杂项目 | 多步骤任务 | `/planning-with-files-zh` | 如果 task_plan.md 不存在 |
| 🧠 设计阶段选择后 | 用户做了 A/B/C 选择 | **见学习闭环（第三支柱）** | 追问决策理由 |

## 第二支柱：🔒 收尾门禁

### 核心原则

**`/clear` 不是命令，是收尾流程的最后一步。在它之前必须通过门禁。**

### 门禁流程

```
阶段完成
  ↓
🧭 顾问触发：检测到收尾信号
  ↓
读取 task_plan.md 的"收尾门禁"清单
  ↓
逐项检查（不是建议，是门禁）：
  [ ] git commit + push 完成？
  [ ] CLAUDE.md 已更新？
  [ ] 双目录同步？（如果本项目需要）
  [ ] 会话已保存？（/save-session）
  [ ] 学习卡已生成？（见第三支柱）
  ↓
全部通过 → 推荐 /clear
任一项未通过 → 阻止 /clear，提示先完成
```

### 禁止行为

- ❌ 在收尾检查全部通过前推荐 /clear
- ❌ 跳过门禁直接推荐 /clear
- ❌ 把门禁项当作"建议"而不是"必须"

### 门禁格式

```
🔒 **收尾门禁** — 在 /clear 之前，以下必须全部完成：

| # | 检查项 | 本项目是否需要 | 状态 |
|---|--------|:---:|------|
| 1 | git commit + push | ✅ 必须 | ✅ / ❌ |
| 2 | 更新 CLAUDE.md | ✅ 必须 | ✅ / ❌ |
| 3 | 双目录同步 | ✅ 必须（本项目铁律） | ✅ / ❌ |
| 4 | /save-session 保存 | ✅ 必须 | ✅ / ❌ |
| 5 | 学习卡生成 | ✅ 必须 | ✅ / ❌ |

通过 N/5 项。全部通过后才能 /clear。
```

## 第三支柱：🧠 学习闭环

### 核心原则

**做完项目不等于学到东西。必须主动制造"停下来想一想"的时刻。**

### 闭环的 4 个环节

| # | 环节 | 何时触发 | 做什么 |
|---|------|---------|--------|
| 1 | 🧠 决策解释 | 设计阶段用户做出选择后 | 追问选择理由 |
| 2 | 👀 过程留痕 | 每个阶段完成时 | 记录做了什么、为什么 |
| 3 | 📝 学习总结 | 收尾门禁最后一步 | 引导用户说出 3 句话 |
| 4 | 📚 学习卡 | /clear 前 | 自动生成 HTML 学习卡存档 |

### 环节 1：决策解释

用户在设计阶段做 A/B/C 选择后，追问：

```
💡 **为什么选这个？** 用一句话说说你的理由。
（这会帮你理清自己的判断逻辑，以后教别人时能用上）
```

注意：
- 只追问"重要的设计决策"（风格、架构、方案），不追问细节
- 用户不想答可以说"跳过"
- 答案记录到 task_plan.md 的决策表（已有"理由"列）

### 环节 2：过程留痕

每个阶段完成时，在 task_plan.md 的决策表中追加。格式已在模板中。

### 环节 3：学习总结

收尾门禁第 5 项触发。引导用户完成 3 句话：

```
🧠 **学习总结** — 在结束前，用 3 句话回顾：

1️⃣ 我做了什么：[用户口述]
2️⃣ 我学到了什么：[用户口述]
3️⃣ 我可以教别人什么：[用户口述]

（你口述，我整理。这是你自己的复盘存档，也是以后教别人的素材。）
```

用户口述后，整理成结构化文本，写入学习卡。

### 环节 4：学习卡

基于以上 3 个环节的积累，自动生成 HTML 学习卡文件。模板在 `templates/project-learning-card.html`。

**命名规则**：`YYYY-MM-DD-<项目简称>-learning-card.html`
**存储位置**：项目根目录（用户可双击在浏览器打开）
**内容来源**：
- 决策表 → "踩过的坑"板块
- 学习总结 → "我学到了什么"板块
- task_plan 阶段列表 → "我做了什么"板块
- 决策表 → "关键技术点"表格

## 推荐格式

每次推荐使用统一格式：

```
🧭 **命令顾问** — 检测到你刚 [完成的动作]

建议你现在使用以下命令：

| # | 命令 | 做什么 | ⚠️ 为什么现在做 |
|---|------|--------|-----------------|
| 1 | `/xxx` | 一句话描述 | 不做会怎样 / 做了的好处 |
| 2 | `/yyy` | 一句话描述 | 可选，但推荐理由 |

💡 **我的建议**：[首选哪个，为什么]

你选哪个？（可以说"都用"、"只做1"、"跳过"）
```

---

## 白名单（不触发推荐）

以下情况**不要跳出来推荐**：
- 用户正在对话闲聊，不是在做事
- 用户明确说了"不用问"、"你自己决定"
- 用户正在执行某个命令/技能的过程中
- 刚推荐过（5 分钟内不重复推荐同一命令）
- 简单到不需要命令的操作（改个文案、回答个问题）

---

## 优先级规则

1. **门禁 > 学习 > 流程**
   - 收尾门禁拦截优先于一切
2. **安全相关 > 流程相关 > 便利相关**
3. **用户正在做的事优先** — 不要打断用户的 flow
4. **一次最多推荐 3 个** — 太多选择 = 没选择
5. **新用户多解释，老用户简洁** — 根据用户的熟练程度调整详细程度

---

## 用户控制

- "顾问关闭" → 暂时禁用所有推荐（门禁也关）
- "顾问启动" → 重新启用
- "门禁不变" → 门禁继续，其他推荐关闭
- "别推荐 /xxx 了" → 禁用特定命令的推荐
- "我知道了" → 跳过本次推荐

## 与哨兵、学习闭环的关系

| 系统 | 职责 | 问的问题 | 比喻 |
|------|------|---------|------|
| 🛡️ 哨兵 | 项目安全 | "出问题了吗？卡住了吗？" | 刹车 |
| 🧭 顾问 | 流程正确 | "该用什么命令？收尾做了吗？" | 导航 |
| 🧠 学习闭环 | 能力成长 | "学到了什么？能教吗？" | 后视镜 |

三者互补，不重复。哨兵喊停，顾问指路，学习闭环确保每一步都变成你自己的东西。
