💡 我学到了什么

  • 新认知

    AI工具的三个系统其实是三层，不是平级的

    之前以为 ai-video-factory、scenefab、agnes-ai 是三个竞品，感到混乱。 实际是：
    • Agnes AI = 能力供应商（菜市场），提供文本/图片/视频 API
    • generate_simple_video.py / scene-fab 源码 = 工具层（厨房设备），执行具体工作
    • Skill（/make-video） = 入口层（菜单），决定用什么设备做什么菜
    按"能力→工具→入口"三层看，就不会乱。不只是视频工具，以后任何工具集都可以这样分层。
  • 新技能

    从 JSONL 日志恢复未写入的文件

    Claude Code 每个会话的完整对话存在 ~/.claude/projects/<项目>/<session-id>.jsonl 里。 当 Write tool call 已发出但未执行完成（终端崩溃），可以在 JSONL 倒数几行找到 tool_use 消息， 里面 content 数组的 input.content 字段就是完整文件内容。tail + jq 或直接读日志即可恢复。 这个技巧值一条命。
    关键路径：~/.claude/projects/E--WorkBuddy-CLAW/<uuid>.jsonl
  • 新方法

    用决策树设计统一入口（而非让用户记多个命令）

    不用让用户知道三个系统，只问一个："做视频，你给的是文案还是视频文件？"
    自动路由：文案→模式A/B，视频文件→模式C。Agnes 自动在后台提供素材，用户不需要知道它的存在。
    这是一种产品设计思路：内部复杂，外部简单。入口越少越好，决策越少越好。
    和 ai-video-factory 的"不提问"哲学一脉相承。

🎓 我可以教别人什么

教程 1：AI 工具多了不要乱——用"能力→工具→入口"三层分层

当你手上有多个 AI 工具不知道怎么用，把它们分成三层看：谁提供能力（API）、谁执行任务（脚本）、谁做入口（Skill/命令）。agenda 在上层，细节在下层。这个框架适用于任何工具集。

教程 2：Claude Code 崩了怎么办——JSONL 日志救文件

~/.claude/projects/<项目>/ 下每个会话有 JSONL 日志。tail 最后几行，tool_use 消息里存着未写完的文件内容。这是救命的，记住。

教程 3：设计统一入口——用决策树替用户做选择

不要给用户 3 个命令让他选。只给一个入口，内部根据输入类型自动路由。内部可以很复杂，外部必须很简单。这是好的产品设计。

教程 4：学习闭环的两种文件——task_plan + HTML学习卡

做完项目不等于学到东西。两种产出物：task_plan.md 记录过程（决策、卡点、阶段），HTML 学习卡做最终存档（可双击浏览器打开、可打印、可分享教学）。缺一不可。

概念/技术一句话解释
JSONL 会话日志Claude Code 把每轮对话存为一行 JSON，位置在 ~/.claude/projects/<项目>/<uuid>.jsonl
tool_use 消息JSONL 中的 assistant 消息类型，content 数组包含 tool name + input 参数，input.content 就是文件内容
MCP (Model Context Protocol)让 LLM 调用外部工具的协议，Agnes AI 通过 MCP server (server.py) 暴露三个工具给 Claude Code
