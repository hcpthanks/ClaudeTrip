激活码云端校验 · 失败全记录 vs 成功方案 · 2026年6月8日—9日

一、目标是什么

给 Claude Code 学习站的激活码系统加云端校验——防止一个激活码被多人分享。服务端记录每个码绑定的设备指纹，超过限额拒绝。

技术选型：腾讯云 SCF（云函数）+ COS（对象存储），零额外费用（全在免费额度内）。

二、6月8日：失败全记录 🔴

耗时约 3 小时，尝试了 7 种方案，全部失败。每一步的错误都指向 SCF 产品本身的坑。

尝试 1
Event 函数 + 在线编辑 + Function URL 失败

创建事件函数，在线粘贴代码，开启函数 URL。

报错：{"errorMessage":"145 code exit unexpected","statusCode":443}

连最简 hello world 都报 145，不是代码问题，是函数 URL 本身的问题。

尝试 2
Web 函数 + scf_bootstrap 放 Node.js 代码 失败

报错：fork/exec ./scf_bootstrap: exec format error

SCF 把 scf_bootstrap 文件当成二进制执行，而不是 Node.js 脚本。

尝试 3
Web 函数 + 根目录 bash scf_bootstrap + src/目录 JS 失败

报错：Unzip entryfile Failded

SCF 找不到根目录的 bootstrap 文件，解压就失败了。

尝试 4
Web 函数 + package.json start 脚本 失败

仍然 exec format error——SCF 强制要求 scf_bootstrap 文件存在。

尝试 5
Function URL 换 API 网关触发器 失败

触发方式列表里显示"不支持 API 网关触发器"。

尝试 6
本地上传 zip 包 失败

报错：Unzip codezip Failded or Zip file format invalid

Windows 下 Compress-Archive 生成的 zip 结构不兼容。

尝试 7
转 Cloudflare Worker 未完成

代码写好了，但用户不熟悉 Cloudflare 英文控制台，找不到 Worker 编辑器入口。

❌ 6月8日结论

SCF 全部路径堵死。Event 函数 + Function URL 报 error 145（即使 hello world），Web 函数 scf_bootstrap 机制与在线编辑不兼容，zip 上传受 Windows 影响。当天放弃，SCF 函数和 Function URL 均已删除。

💡 根因分析

参数兼容模式是 Function URL 与 Event 函数之间的桥梁。

Event 函数的 main_handler(event) 期望接收 API 网关格式的 event 对象（含 event.httpMethod、event.body、event.headers 等字段）。

不开启参数兼容时，Function URL 传给 event 的是原始 HTTP 请求格式——字段名不同、结构不同。函数解析不到 event.body，就报 error 145。

开启后，Function URL 自动把请求转换成 API 网关格式，函数就能正常工作了。

五、攻略：从零部署 SCF Event 函数

前置条件

  • 腾讯云账号（已实名认证）
  • 一个 COS 存储桶（私有读写，同地域）

5.1 创建 SCF 函数

  1. 控制台搜索 "云函数" → 进入函数列表
  2. 点击 新建函数 → 选 从头开始
    不要选 Web 函数、不要选模板
  3. 填写：
函数类型事件函数（Event）
函数名称cc-activation-verify
地域与 COS 桶相同
运行环境Node.js 18.x

5.2 粘贴代码

函数代码 → 在线编辑 → 全选删除 → 粘贴代码。

代码末尾 handler 必须是 exports.main_handler = async function (event) { ... }。

返回格式必须是 { statusCode, headers, body }。

5.3 配置环境变量

COS_BUCKETcc-activation-1253632363
COS_REGIONap-beijing

5.4 配置运行角色

  1. 函数配置 → 运行角色 → 新建角色
  2. 角色载体：腾讯云产品服务 → 选择 云函数（SCF）
  3. 权限策略：搜索并勾选 QcloudCOSFullAccess
  4. 角色名填 SCF_COS_Access → 完成
  5. 回到函数页，运行角色下拉选 SCF_COS_Access

5.5 创建函数 URL ⭐

  1. 函数详情页 → 函数URL → 新建函数URL
触发别名LATEST
授权类型开放（不需要 CAM 认证）
参数兼容⚠️ 必须开启！
CORS不开启（代码自带）
  1. 创建 → 复制 HTTPS 公网访问路径
  2. 填入前端 recover.html 的 API_BASE

5.6 测试

curl -X POST "你的函数URL" \
  -H "Content-Type: application/json" \
  -d '{"code":"CC-ATEST-AAAA-CCCC","fingerprint":"test-001"}'

# 预期返回：{"ok":false,"error":"激活码无效"}
# 如果返回这个，说明函数在正常运行 ✅

5.7 部署检查清单

  • COS 桶存在，私有读写
  • SCF 函数类型 = Event 函数
  • 环境变量 COS_BUCKET + COS_REGION 已配
  • 运行角色已绑定 COS 权限
  • 函数 URL 参数兼容 = 已开启
  • 函数 URL 授权类型 = 开放
  • curl 测试返回正常 JSON（不是 error 145）
  • 前端 API_BASE 已更新为函数 URL

七、踩坑经验总结

📌 记住这几条

  1. 只用 Event 函数，别碰 Web 函数。 Web 函数的 scf_bootstrap 机制对在线编辑不友好，Windows 下几乎无法正确上传。
  2. 参数兼容模式是救命开关。 不开 = error 145，开了 = 正常工作。这是今天和昨天的唯一本质区别。
  3. CORS 别在 Function URL 里开。 那个表单校验很严格（Origin 必须带 https://，Headers 不能空），代码里写 CORS 响应头更可控。
  4. API 网关产品已停服。 2025 年 6 月 30 日下线，新老用户都不能用了，不用再试。
  5. 别在 Windows 上打 zip 上传。 要用在线编辑器贴代码，这是唯一可靠的上传方式。
  6. 运行角色自动注入密钥。 SCF 执行角色绑定 COS 权限后，不需要手动配 TENCENTCLOUD_SECRETID 环境变量，运行时会自动注入临时密钥。
