🔄 每日工作流实战

单个命令只是工具，串起来才是生产力。三种模式，覆盖你 90% 的工作场景。

① 标准开发流 ② 快速修复流 ③ 学习研究流 ④ 日常运维流 ⑤ 怎么选 ⑥ 练习

① 模式 A：标准开发流（最推荐）

适用于：写新功能、做重构、任何需要"从零到完成"的任务。

/plan
制定计划
→
确认方案
检查是否正确
→
/tdd
测试驱动开发
→
/code-review
代码审查
→
/verify
完整验证
→
/save-session
保存进度

为什么这样走：

  • 先计划 → 不会跑偏
  • 再 TDD → 有测试保护，改不坏
  • 审查 → 抓低级错误
  • 验证 → 确认能跑
  • 保存 → 明天继续
💡 早上打开电脑，敲 /plan 我今天要做的事情，然后顺着流程往下走。一天的工作不跑偏。

② 模式 B：快速修复流

适用于：线上报 Bug、用户说某个功能坏了、需要快速定位并修好。

描述Bug
"点击登录没反应"
→
Claude分析
定位根因
→
/tdd
先写复现测试
→
修复代码
Claude 改代码
→
/verify
验证修复
💡 关键一步是先写复现测试——确保这个 Bug 以后不会再偷偷回来。

③ 模式 C：学习研究流

适用于：学新技术、研究不熟悉的代码、想理解某个概念。

问问题
"Rust所有权怎么理解？"
→
Claude讲解
带代码示例
→
动手练习
跟着写代码
→
/learn-eval
提取知识点
→
/evolve
进化成技能
💡 学完一定要用 /learn-eval 保存知识点。不然过两天全忘了，等于白学。

④ 模式 D：日常运维流

适用于：安装依赖、查日志、切换分支、部署等日常操作。

!命令
快速执行 shell
→
@文件名
快速定位文件
→
/docs 包名
查文档
→
/@git log
看提交历史
💡 ! 开头直接跑 shell 命令，@ 加文件名快速读文件。不需要每次都说"帮我执行..."。

⑤ 怎么选

你遇到的情况用哪个模式
要加新功能模式 A：标准开发流
线上出 Bug 了模式 B：快速修复流
想学点新东西模式 C：学习研究流
日常杂活（装包/查日志/部署）模式 D：日常运维流

⑥ 练习

  1. 找一个小功能，用模式 A 完整走一遍（/plan → /tdd → /code-review → /verify）
  2. 找一个以前修过的 Bug，用模式 B 的思路复盘（当时有没有先写复现测试？）
  3. 选一个你不懂的技术概念，用模式 C 学习，最后用 /learn-eval 保存
