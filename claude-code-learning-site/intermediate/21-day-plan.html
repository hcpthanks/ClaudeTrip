🌱 第一周：基础入门（7天打牢基本功）

💡 点击每个任务展开详细步骤。第一周不要求做什么大项目——把7个核心命令用顺手就行。

  • 第1天：用 /plan 规划一个小功能，确认后再继续 ▶

    目标：学会在做事之前先让 AI 做计划。这能省你大量来回修改的时间。

    ① 打开 Claude Code

    按键盘左下角的 Win 键（四个方块那个）→ 输入 powershell → 回车。黑色窗口出来后输入 claude 回车。

    （如果你还没安装 Claude Code，先回到预备课第3节"安装 Claude Code"）

    ② 告诉 Claude 你要做什么

    不用敲 /plan，直接说话就行。比如：

    我想给学习站首页加一个搜索框，让用户可以搜课程名称。帮我做个计划。

    或者用你自己项目里的一个小需求。关键是——先不要让它写代码，只要计划。

    ③ 看 Claude 的计划

    Claude 会列出：涉及哪些文件、分几步、每步做什么。仔细看一遍。

    ④ 确认或修改

    如果计划没问题 → 回复 "好的，开始吧"。如果有想改的 → 直接说"第2步不用做，换一个方案"。

    确认后 Claude 就会开始写代码。

    Q: 我不知道要做什么小功能怎么办？

    A: 随便找一个都行。比如"在网页上加一个回到顶部的按钮"、"把页面背景色调深一点"。目的不是做功能，是练 /plan 的流程。

    Q: Claude 的计划太复杂了？

    A: 直接说"太复杂了，简化一下，只做最核心的部分"。

  • 第1天：用 /tdd 完成测试驱动开发 ▶

    目标：学会"先写测试再写代码"。养成这个习惯后，你的代码出 bug 的概率大幅降低。

    ① 接着上面的 /plan 做

    上一步你让 Claude 做了计划。现在告诉它：

    /tdd 按照刚才的计划，先写测试
    ② 看 Claude 写测试

    Claude 会先写一个测试文件（比如 xxx.test.js）。这个测试目前会失败——这是正常的（红色阶段）。

    ③ Claude 写代码让测试通过

    测试写完后，Claude 会自动写代码让测试变绿。你不用操作，看着就行。

    ④ 测试通过后

    如果 Claude 问你要不要重构，回答"好的"。重构就是让代码更整洁，但不改变功能。

    Q: 我的项目没有测试框架怎么办？

    A: Claude 会自动帮你装。它检测到项目没有测试工具会自动配好。

    Q: 测试一直失败？

    A: 把错误信息复制给 Claude，说"这个测试没通过，帮我看看为什么"。

  • 第2天：用 /code-review 审查自己写的代码 ▶

    目标：学会让 AI 帮你检查代码。就像写完作业让同桌帮看一眼——但 AI 不会漏任何错误。

    ① 打开你昨天改过的项目

    打开 PowerShell → cd 你的项目文件夹 → claude

    ② 敲审查命令
    /code-review

    不需要指定文件——Claude 会自动检查你改动过的代码。

    ③ 看审查结果

    Claude 会列出发现的问题，分四个等级：

    • CRITICAL（严重）：安全漏洞，必须修
    • HIGH（高）：Bug 或逻辑问题，应该修
    • MEDIUM（中）：代码质量建议，建议修
    • LOW（低）：小建议，可选
    ④ 让 Claude 修复

    如果有问题，直接说：

    帮我把 CRITICAL 和 HIGH 的问题都修了

    Q: 我没有改动过的代码怎么办？

    A: 随便写几行代码再跑。哪怕故意写个 console.log 都行——审查会发现它。

  • 第2天：用 /build-fix 修复一个构建错误 ▶

    目标：构建报错不用慌，一条命令让 AI 帮你修。

    ① 先尝试构建

    在 Claude Code 里敲：

    !npm run build

    （! 开头表示直接执行命令，不用 AI 思考。如果你的项目用的不是 npm，改成对应的命令，比如 !pnpm build）

    ② 如果报错了（大概率会）

    看到红色错误信息不用管——直接敲：

    /build-fix
    ③ 让 Claude 自己修

    Claude 会分析错误、改代码、再构建。一次修不好会自动继续。你喝口水等着就行。

    Q: 我的项目没有构建错误？

    A: 那太好了！说明你的代码质量不错。今天这个任务打个勾直接过。

  • 第3天：用 /verify 做完整验证 ▶

    目标：提交代码之前跑一遍全面检查——构建、测试、类型检查一步完成。

    ① 打开你的项目

    确保你有一些改动过的代码（前两天的就行）。

    ② 敲验证命令
    /verify
    ③ 等结果

    Claude 会依次跑：类型检查 → Lint 检查 → 测试 → 构建。全部通过会告诉你"验证通过"。

    如果有失败的，Claude 会自动尝试修复。

    Q: /verify 和 /build-fix 有什么区别？

    A: /build-fix 只修构建错误。/verify 是全面检查——构建、测试、代码风格、类型全部跑一遍。提交之前跑 /verify，平时修错用 /build-fix。

  • 第3天：用 /save-session 保存会话，再用 /resume-session 恢复 ▶

    目标：学会"存档"和"读档"。就像打游戏——打到一半存个档，下次接着打。

    ① 在对话中间保存

    当你跟 Claude 聊到一半（比如刚做完一个重要功能），敲：

    /save-session

    Claude 会生成一个会话文件，保存当前所有对话上下文。

    ② 关掉 Claude Code

    直接按 Ctrl+C 退出，或者把 PowerShell 窗口关掉。

    ③ 重新打开，恢复对话

    重新打开 PowerShell → claude → 然后敲：

    /resume-session

    Claude 会列出最近的会话文件。选刚才那个 → 你的对话就回来了，跟没关过一样。

    Q: 为什么要保存会话？

    A: 两个原因：① 下班了明天继续；② 对话太长 Claude 开始"健忘"了，存一下重新开始更清爽。

  • 第4天：用 /docs 查文档 ▶

    目标：以后不用打开浏览器搜文档了。想知道什么库怎么用，直接在 Claude Code 里问。

    ① 想一个你想了解的库或工具

    比如想知道 React 某个功能怎么用、想查 Tailwind CSS 某个类的写法。

    ② 敲文档命令
    /docs react useEffect 怎么用

    把 react useEffect 怎么用 换成你想查的东西。格式是：/docs 库名 问题

    ③ 换 5 个不同的问题试试

    比如：

    • /docs tailwindcss 响应式布局
    • /docs express.js 路由怎么写
    • /docs git 撤销上一次提交
    • /docs markdown 表格语法
    • /docs node.js 读文件
  • 第4天：用 /refactor-clean 清理死代码 ▶

    目标：学会清理"垃圾代码"——那些写了但从来没人用的函数、变量、文件。

    ① 打开你的项目
    ② 敲清理命令
    /refactor-clean
    ③ 看 Claude 发现了什么

    Claude 会列出项目里所有"可能没用"的代码：没被引用的函数、重复的代码块、没用的文件。

    确认没问题 → 说"帮我清理掉"。

    Q: 万一删了有用的代码？

    A: 用 git 可以撤销。敲 !git diff 看改了什么，敲 !git checkout . 可以撤销所有改动。所以放心试。

  • 第5天：练习键盘快捷键 ▶

    目标：学 5 个最常用的快捷键。不用鼠标就能操作 Claude Code，效率直接翻倍。

    快捷键做什么什么时候用
    Ctrl+U清空输入框想重新输入的时候
    Shift+Enter换行想输入多行文字的时候（直接回车会发送）
    Esc Esc中断 AIAI 在胡说八道或者写偏了，连按两下 Esc 让它停下
    Ctrl+O看 AI 的思考过程想知道 AI 为什么做出这个决定
    Ctrl+R搜索历史命令想找回之前输入过的一条命令
    ① 打开 Claude Code，每个快捷键按一遍试试
    ② 今天用的时候，刻意不用鼠标，只用键盘
  • 第5天：用 /learn-eval 从对话中提取经验 ▶

    目标：让 AI 记住你今天学到的东西。以后它会自动用这些经验。

    ① 在你完成一个任务之后敲
    /learn-eval
    ② Claude 会分析刚才的对话

    它会提取：你用的什么命令、遇到了什么问题、用了什么解决方案。然后问你要不要保存为"记忆"。

    ③ 回答"好的"

    以后在新的对话里，Claude 会自动参考这些经验。

    Q: 这个和 /save-session 有什么区别？

    A: /save-session 保存的是"对话内容"（一次性的）。/learn-eval 保存的是"经验教训"（永久的，跨对话有效）。

  • 第6天：用 /context-budget 检查上下文使用情况 ▶

    目标：学会看"AI 还剩多少记忆空间"。满了它就会变笨。

    ① 在跟 Claude 聊了一段时间后敲
    /context-budget
    ② 看返回的信息

    会显示：总共 200K tokens，已用 XX%，还剩 XX%。还会列出什么东西在占空间。

    ③ 如果快满了（超过 80%）

    有两个选择：

    • 压缩：敲 /compact，让 AI 把对话"压缩"一下，保留关键信息
    • 新开对话：敲 /save-session 保存当前进度，然后新开一个 Claude Code 窗口继续

    Q: 上下文满了会怎样？

    A: Claude 会"忘记"对话最前面说过的话。你可能需要重新说一遍要求。这就是为什么有时候 Claude 变笨了——不是它笨，是上下文满了。

  • 第6天：用 /checkpoint 在关键节点打标记 ▶

    目标：学会"存档点"——关键时刻留个备份，做坏了可以回退。

    ① 在重要操作之前敲

    比如要做一个大改动、要删除一批文件、要重构一段复杂代码——在动手之前敲：

    /checkpoint
    ② 取个好记的名字

    Claude 会问你给这个检查点起什么名字。起个能看懂的名字，比如"重构之前的版本"、"加搜索功能之前"。

    ③ 放心改

    万一改坏了 → 告诉 Claude "回退到上一个 checkpoint" → 一切恢复原样。

    Q: 打的 checkpoint 能存多久？

    A: 在当前对话里一直有效。对话关了 checkpoint 就没了。所以这是"临时存档"，不是永久备份。

  • 第7天：完整走一遍"标准开发流" ▶

    目标：把前6天学的串起来，完整走一遍。这是你以后每天的标准操作流程。

    ① 找一个小功能做

    随便想一个就行。比如"给页面加一个夜间模式开关"、"把字体调大一点"。

    ② 按顺序走这 6 步

    1️⃣ /plan 我想做XXX，帮我做计划

    2️⃣ 确认计划 → /tdd 按计划开始

    3️⃣ 代码写完 → /code-review

    4️⃣ 如果有问题 → /build-fix

    5️⃣ 提交前 → /verify

    6️⃣ 完成 → /save-session 保存

    ③ 感受一下

    走完这 6 步，你刚完成了一次"零事故开发"——有计划、有测试、有审查、有验证。这就是专业开发者的工作方式。以后每次写代码都这么走。

  • 第7天：用 /pr 创建第一个 PR ▶

    目标：学会用一条命令把你的改动提交到 GitHub。

    ① 确保你的改动已经提交

    在 Claude Code 里敲 !git status 看一下有没有未提交的改动。

    如果有 → 说"帮我把这些改动提交并推送"。

    ② 创建 PR
    /pr

    Claude 会自动分析你的改动 → 写 PR 描述 → 推送到 GitHub → 创建 Pull Request。

    ③ 打开 GitHub 看看

    Claude 会给你一个链接。打开看——那就是你的 Pull Request。别人可以在这里审查你的代码、提意见。

    Q: 我的项目没连 GitHub 怎么办？

    A: 那就先跳过这一步。或者告诉 Claude"帮我把这个项目推送到 GitHub"，它会一步步教你。

④ 怎么坚持 21 天

  • 每天只做 1-2 项——每项大约 10-15 分钟
  • 点开"📖 怎么做"跟着做——不需要动脑想，跟着步骤走就行
  • 不要跳——前一周必须打牢，后面才跟得上
  • 勾了才算——每做完一项立刻勾上，看进度条涨有成就感
  • 忘了一天别放弃——第二天补上就行，不用从头来
💡 21 天后，这些命令会形成肌肉记忆。就像学开车——一开始每个动作都要想，后来想都不用想。你不再是一个"会用电脑的人"，而是一个"能指挥 AI 干活的人"。
