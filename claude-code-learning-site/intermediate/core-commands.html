⚡ 核心命令精通

这7个命令是你每天都会用到的。新手知道"有这个命令"，高手知道"什么时候用、跟什么组合用"。

① 总览 ② /plan ③ /tdd ④ /code-review ⑤ /build-fix ⑥ /verify ⑦ /save-session ⑧ /learn-eval ⑨ 组合技

① 七个命令一张表

命令做什么什么时候用
/plan做事之前先计划开始任何新任务之前
/tdd测试驱动开发写新功能、修 Bug
/code-review代码审查每次写完代码后
/build-fix自动修复构建错误构建失败时
/verify完整验证流程提交之前
/save-session保存当前会话下班前、切换任务前
/learn-eval从对话中提取经验完成一个重要任务后
如果你是新手，这周只练这 7 个就够了。熟练之后再看其他命令。

② /plan — 做事之前先想清楚

/plan
开始任何任务前先做计划，确认后再写代码。不浪费 token。
💡 场景：要加新功能、做重构、或者你自己还没想清楚要做什么的时候

怎么用：

  1. 告诉 Claude 你要做什么："我想给网站加一个搜索功能"
  2. Claude 输出实现计划（分几步、涉及哪些文件）
  3. 你确认后 → Claude 才开始写代码
💡 核心价值：防止 Claude 一上来就写代码然后写偏了。计划阶段不花钱（用的小模型），改计划比改代码快 10 倍。

③ /tdd — 先写测试，再写代码

/tdd
测试驱动开发：先写测试→写代码→验证覆盖率≥80%
💡 场景：写新功能、修 Bug、重构老代码

三步走：

  1. 红（RED）：Claude 先写一个会失败的测试
  2. 绿（GREEN）：写最少代码让测试通过
  3. 重构（IMPROVE）：优化代码，保持测试通过
💡 好处：先写测试等于先确定"什么叫做好了"。代码写完测试自动验证，不用手动测。

④ /code-review — 每写完代码都要审查

/code-review
检查安全漏洞、代码质量、最佳实践、命名规范
💡 场景：每次写完一段代码后，提交之前

审查什么：

  • 安全漏洞（密码泄露、注入攻击）
  • 代码质量（函数太长、嵌套太深）
  • 性能问题（N+1 查询、没加分页）
  • 测试覆盖（少了什么测试）

⑤ /build-fix — 构建挂了自动修

/build-fix
自动检测项目类型，分析错误，增量修复构建问题
💡 场景：npm build 报错、tsc 类型检查失败、import 找不到

不需要手动看报错，敲 /build-fix 然后让它自己修。修完一个验证一个，不会把其他东西弄坏。

⑥ /verify — 提交之前做一次全面检查

/verify
完整验证流程：构建→Lint→测试→类型检查，一步跑完
💡 场景：要提交代码之前、要合并 PR 之前
💡 把这个当成"出门前照镜子"——提交之前跑一遍，确保没有低级错误。

⑦ /save-session — 下班保存，明天继续

/save-session
保存当前会话到文件，第二天用 /resume-session 无缝接着干
💡 场景：下班了、要切到另一个任务、或者对话已经很长了想保存进度

⑧ /learn-eval — 让 AI 从你的对话里学东西

/learn-eval
从当前对话中提取可复用的经验、模式、知识点，保存为记忆或技能
💡 场景：完成一个重要任务后、发现一个新的好用的写法时
💡 越用越聪明：每次用 learn-eval 提取经验，下次 Claude 自动记得你的偏好。

⑨ 组合技 — 串起来用才厉害

单个命令只是工具，串起来才是工作流：

标准开发流
/plan → 确认 → /tdd → /code-review → /verify → /save-session
每天早上打开电脑，走这个流程，一天的工作不跑偏。
快速修复流
描述 Bug → Claude 分析 → /tdd（写复现测试）→ 修复 → /verify
线上报 Bug，需要快速定位并修复。
